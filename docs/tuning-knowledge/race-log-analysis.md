# Blackboxからレースのブレを調べる手順

[文書集の入口](README.md)

## 1. まず記録が何を表すかを確認する

BBLのファイル名だけではなく、原本のSHA256と0始まりのsection番号を記録します。
一つのBBLに複数のフライトがある場合、対象のsectionを取り違えないようにします。
原本は編集せず、変換や追加解析は別の出力として残します。

| 確認対象 | 理由 |
|---|---|
| FW revision、解析ソフトの版・条件 | 同じログでも解析方法の変更で結果が変わるため |
| 各信号の単位と記録有無 | 欠測を0にしたり、パーサーの既定値を記録設定と誤認したりしないため |
| 実タイムスタンプ、周期、欠測、破損 | 表示用に間引いた系列や欠測越しの補間でFFT・継続時間を計算しないため |
| gyro取得・PID計算・ログ記録の各周期 | これらは同じ周期とは限らず、微分やフィルターの解釈が変わるため |
| モーター極数とRPMの換算 | 電気回転数と機械回転数を混同しないため |
| 電圧・電流の校正、パックの識別 | 電池の個体差、消費、劣化を不用意に断定しないため |

BBLは完全な現在設定バックアップではありません。変更を提案する段階では、
現FCのversion・対象プロファイル・設定バックアップも確認します。

## 2. 見た目の症状を短い区間へ絞る

DVRがある場合は、問題の瞬間だけでなく、その前の操縦・負荷変化と収束後も見ます。
最初の目安として前約1秒、後約0.5秒を開き、必要に応じて広げます。
これは原因を決める時間閾値ではありません。

動画とBBLの時計は別です。offsetと時計倍率、その根拠と不確かさを保存し、
新しい動画に前回のoffsetを流用しません。数十ms程度の動画同期を、1ms精度の制御遅延測定に使わないことが重要です。
動画がなくてもログ上の調査はできますが、「映像でも同じブレ」と確認したかは区別します。

## 3. 操縦由来の回転と、要求にない往復を分ける

同じ軸のsetpointとgyroを重ねます。ここでgyroは回転速度であり、姿勢角そのものではありません。
要求が大きく変化した結果の回転と、要求にない周期的な往復を分けて見ます。

平均誤差や全フライトのovershootだけで、特定ターンの原因を決めません。
要求・gyro・誤差それぞれの帯域成分、実波形、ピークの数、収束の仕方も確認します。
短いバーストに数周期しかない場合、周波数や減衰の推定精度には限界があります。

周波数×RPMの図は、回転数に追随する成分と、固定周波数付近の成分を分ける材料になります。
ただし、帯の形だけで機械共振やモーター故障を確定するものではありません。

## 4. 同じ時刻の制御・出力・電源を並べる

| 見るもの | 分けて考えること |
|---|---|
| P/I/D/FF | 補正が動いた事実と、その補正が適切だったかは別 |
| Iと導出・記録された上限 | Iが大きいことと、上限張り付きは別 |
| D Max、実TPA | TPA前のD係数、TPA後のD出力、未記録の倍率を混ぜない |
| 各モーター指令の上限・下限 | 4基平均では隠れる出力差と制限を見る。実推力の測定ではない |
| 電圧・電流・負荷の変化 | 電圧低下が振動の前か後か、更新周期は十分かを見る |
| gyro・Dの高周波成分、着陸後温度 | 低帯域の減衰だけを改善して、ノイズや発熱を悪化させない |

振動に伴ってPが増えるのは、誤差からPを計算していることとも整合します。
「振動側のPが大きい」は、それだけでP過大という独立した証拠にはなりません。
motor上下限や電圧低下も原因になり得ますが、振動の結果でもあり得ます。

## 5. 安定していたターンと比較する

なるべく同じFW・設定・機体・パック条件で、操縦要求・スロットル・電圧が近い区間を探します。
要求の平均値だけでなく、窓内の波形と直前の履歴も見ます。
振動、gyro誤差、I、motor等の結果を入力マッチの距離へ入れると、比較したい差を消してしまいます。

近い対照がなければ不成立のまま残します。条件を緩めて同条件のA/Bができたことにせず、
参考例として見せる場合は、何が揃っていないかを示します。
100ms刻みの重なった解析窓を、独立した10回のターンや反復として数えません。
候補窓の統合範囲も、実際の振動の持続時間とは限りません。
抽出条件に通らない大きな誤差は、安定と分類せず、別の確認対象として残します。

## 6. フィルターの位相差を扱う場合

ノイズの減少と、処理経路の位相差を両方見ます。信号の弱い帯域の推定は保留します。
窓長、detrend、FFTサイズを変えて結果がどれだけ動くか、既知フィルターの対照で偏りが出ないかも確認します。

- `-phase / (2*pi*f)` のms換算は、その周波数の位相遅れ相当です。
- 群遅延、一定時間の遅れ、RCからモーターまでの遅延、ループ全体の位相余裕とは別です。
- gyroからDを見る場合、Dの負の微分そのものの位相を除かずにフィルター遅れと数えないようにします。
- 短い窓での高coherenceだけでは、推定が正確とは保証できません。
- 既存信号に別フィルターをかけた図は、設定変更後の閉ループ機体運動の予測ではありません。

## 7. 一つの仮説を再フライトで確かめる

Pを下げる、Dを上げる、フィルターを変える、パックを替える、といった変更を一度に重ねません。
最初に何を改善したいか、何が悪化したら戻すか、実際にどの値が変わったかを記録します。
設定A→変更B→設定Aの比較は有用ですが、同じパックを放電しながら繰り返せば電源条件は変わります。

入力を滑らかにする試験は、過渡負荷との関係を調べるための試験です。
遅く飛んだだけの差をチューニング改善にしません。
最終受入は普段のレース操作で、対象のブレ・追従・ライン保持・出力制限・高周波・温度を確認します。

結果は「改善」「悪化」「比較不能」を残し、必要な評価が成立した場合だけ、
その範囲で追加変更不要と判断します。データ不足や候補0件を、健康な機体という判定にしません。
